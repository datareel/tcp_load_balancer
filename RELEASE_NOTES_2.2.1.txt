DRLB 2.2.1 release notes
DRLB TCP load balancer, 11/28/2026 (planned, after a week of testing
on the OSA and OCA replication tunnel)

Changes since 2.2.0
-------------------
* Port multiplexer (mode = MUX): a tunnel closed by the keepalive
  timeout (nothing received for 3 x mux_keepalive_secs) now logs why
  and the socket's TCP state, for example:
    closed: no data from the peer for 46 secs (network or peer down),
    tcp: retransmits 6 (total 9), rto 25600 ms, unacked 3, last recv
    46012 ms ago, last ack 45980 ms ago, rtt 43 ms, queued 0
  Retransmits, a backed off rto and unacked data mean the network path
  to the peer was lost; no retransmits and no unacked data mean the
  peer itself stopped answering. The TCP state is read only when the
  tunnel is closed.
* User guide ("Stats and logs" in "Port multiplexer"): what the
  keepalive timeout means, the reconnect and client hold that follow,
  how a lower or higher mux_keepalive_secs changes detection, and how
  to read the TCP state.
* tests/mux_tests.py (39 checks): a peer that stops answering is closed
  with the new log line and A reconnects when it answers again.

Upgrading
---------
* From 2.2.0: a plain dnf upgrade. No config, setting or wire protocol
  change: a 2.2.1 server works with 2.2.0 peers, so the two ends of a
  tunnel can be upgraded one at a time.
* The load balancer and SSL bridge (mode = LB, the default) are
  unchanged.

Packaging
---------
* drlb_server-2.2.1-1 (RHEL 10, 9, 8 FIPS build) and
  drlb_server-openssl35-2.2.1-1 (RHEL 8). --version prints 2.2.1.
